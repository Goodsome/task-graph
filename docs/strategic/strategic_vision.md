# 战略业务愿景 (Strategic Vision)

## 1. 北极星目标 (North Star Metric)
构建一个**由 AI Agent 驱动的、基于 DAG (有向无环图) 的智能任务编排与问题追踪系统**。
系统通过将非结构化的外部反馈（Issue）转化为结构化、具备依赖关系的自动化执行单元（Task），实现研发全链路的闭环管理与 ROI (投资回报率) 驱动的最优路径决策。

## 2. 业务领域划分 (Domain Partitioning)

### 核心域 (Core Domain): Planning (任务规划与编排)
*   **业务价值**：这是系统的核心竞争力所在。它不仅管理任务的生命周期，更通过 DAG 引擎解决了复杂的依赖追踪、循环依赖检测以及基于 ROI 的执行优先级建议。
*   **复杂度**：高。包含复杂的领域逻辑，如任务的状态自动流转算法、ROI 计算模型以及跨项目的依赖网路管理。
*   **演进方向**：持续优化 Agent 的规划能力，支持更深层次的层级拆解（Initiative -> Milestone -> Task）和跨团队协作。

### 支撑域 (Supporting Domain): Issue Tracking (问题追踪)
*   **业务价值**：作为系统的“流量入口”，负责收集并管理来自第三方用户或系统的原始反馈。它为核心域提供待处理的输入源，并维持与外部提交者的沟通闭环。
*   **复杂度**：中。主要侧重于规范化的生命周期管理（NEW -> CLOSED）和评论/标签的 CRUD 操作，逻辑相对标准。
*   **演进方向**：增强与核心域的联动，支持从 Issue 到 Task 的自动化预评估与分类建议。

## 3. 架构与基础设施 (Architecture & Infrastructure Foundations)

这些组件不属于业务领域，但作为技术底座支撑着上述限界上下文运行：

### 共享内核 (Shared Kernel)
*   **职责**：定义全系统通用的领域基础类（如 `Entity`, `ValueObject`, `AggregateRoot`）、全局配置、统一的事件总线协议以及 ORM 映射基类。
*   **原则**：保持高度稳定，仅包含跨领域必须共享的契约。

### 组合根与依赖注入 (Bootstrap)
*   **职责**：负责系统的启动、配置加载、日志初始化以及依赖容器（Container）的装配。
*   **技术细节**：使用组合根模式确保各个模块的解耦，并在运行时动态注入适配器。

### 主动适配器 (Entrypoints)
*   **职责**：系统的外壳层，负责将外部请求（如 MCP 协议、CLI 命令）映射到应用层的用例（Use Cases）。
*   **包含内容**：MCP Server 适配器、命令行交互入口。
